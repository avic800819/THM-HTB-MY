==================================================
【Linux 筆記】systemd 服務類型 (Type=) 與資安防禦重點
==================================================

一、6 大常見 systemd 服務類型 (Type=) 速查
--------------------------------------------------

1. simple（預設值）
   - 直覺比喻：直覺外送員
   - 判定標準：指令一下去執行，就直接算成功。
   - 實戰情境：一般沒特別指定的服務、最基礎的背景常駐程式。
   - 備註：若設定檔中完全沒寫 Type=，預設就是 simple。

2. dbus（HTB 考點）
   - 直覺比喻：對講機報備員
   - 判定標準：必須向系統內部通訊匯流排 (D-Bus) 註冊廣播自己的名字才算成功。
   - 實戰情境：涉及跨程式通訊的守護行程。
   - 資安關聯：Linux 本地提權 (LPE, 如 Polkit 漏洞) 的常見破口。

3. oneshot
   - 直覺比喻：一次性免洗工具人
   - 判定標準：任務執行完畢行程完全退場，才算成功。
   - 實戰情境：開機初始化、備份任務、快取清理等批次腳本。

4. forking
   - 直覺比喻：老闆分身術
   - 判定標準：主行程啟動後產生子行程並退出，systemd 轉為追蹤留在背景的子行程。
   - 實戰情境：傳統經典伺服器程式（如 Nginx、Apache、老牌 Daemon）。

5. notify
   - 直覺比喻：主動打卡員
   - 判定標準：程式執行完畢後，自己發送 sd_notify 訊號主動向 systemd 報備。
   - 實戰情境：現代高可靠性伺服器軟體。

6. idle
   - 直覺比喻：大牌遲到者
   - 判定標準：等待系統其他開機任務排空後才開始執行。
   - 實戰情境：避免開機時搶佔主控台螢幕輸出或 CPU 的次要工作。


二、解題反射口訣
--------------------------------------------------
1. 題目問 Service Type 毫無頭緒：
   猜測順序：simple -> oneshot -> forking -> dbus
2. 題目提到「通訊、匯流排、BusName」：dbus
3. 題目提到「跑一次就結束、批次腳本」：oneshot
4. 題目提到「產生子行程、傳統 Daemon」：forking


三、實戰終端機指令（Bash 環境）
--------------------------------------------------
1. 檢查目前是否在 Bash：
   若看到「PS >」代表在 PowerShell，請先輸入：bash

2. 查看服務設定檔完整內容：
   systemctl cat <服務名稱>.service

3. 全系統搜尋找不到的服務檔：
   sudo find / -name "*<關鍵字>*" 2>/dev/null

4. 撈取所有已啟用 (enabled) 的服務清單：
   systemctl list-unit-files --type=service --state=enabled


四、資安防禦（藍隊巡檢／排查）3 大核心
--------------------------------------------------
口訣：看路徑、看權限、看 ExecStart

1. 檢查後門常駐 (Persistence)：
   - 檢查最近 24 小時被變更或新增的服務：
     find /etc/systemd/system/ -type f -mtime -1
   - 檢查 ExecStart 指向的執行檔是否可疑（如指向 /tmp、/dev/shm 或包含 bash 反彈代碼）。

2. 檢查提權弱點 (Privilege Escalation)：
   - 檢查是否有一般使用者具備寫入權限的服務檔：
     find /etc/systemd/system/ -perm -o+w -type f 2>/dev/null

3. 日誌與軌跡調閱 (IR/SOC)：
   - 查看特定服務的詳細日誌紀錄：
     journalctl -u <服務名稱>.service --since "1 hour ago"

========================================================================================================================
五、 系統黑盒子：Linux 關鍵日誌稽核 (Logging & Audit)
========================================================================================================================
1. 核心觀念：
   Linux 的「行車記錄器總庫」位於 /var/log/。
   任何連線嘗試、密碼認證、sudo 提權行為與系統異常，都會在此留下數位足跡。

2. 藍隊/調查必看 4 大核心日誌檔：
   - /var/log/auth.log   ：【最重要】身分驗證日誌（Ubuntu）。記錄 SSH 登入成敗、sudo 指令軌跡、su 切換帳號。
                           (備註：CentOS/RHEL 系統中檔名為 /var/log/secure)
   - /var/log/syslog     ：系統綜合事件日誌。全系統背景服務與核心運行狀況。
   - /var/log/nginx/     ：網頁存取與報錯日誌（包含 access.log 與 error.log）。
     (或 /apache2/)       查訪客來源 IP、存取了什麼 URL、是否有 SQL 注入或目錄爆破痕跡。
   - /var/log/ufw.log    ：內建防火牆日誌。記錄哪些連線被防火牆阻擋 (BLOCK) 或放行。

3. 常用日誌調閱排查指令：
   - 即時追蹤最新連線日誌（動態監看）：
     tail -f /var/log/auth.log
   - 抓出所有登入失敗的暴力破解紀錄：
     grep "Failed password" /var/log/auth.log
   - 抓出所有曾被執行的 sudo 高權限指令：
     grep "COMMAND" /var/log/auth.log

4. 攻守實戰要點：
   - 藍隊防禦：定期透過 SIEM 撈取 auth.log 的異常來源 IP，掌握內網失陷指標 (IoC)。
   - 紅隊手法：完成提權後會嘗試清除或篡改 /var/log/ 內容以隱匿痕跡；進階防禦會將日誌即時推送到獨立日誌伺服器防止被抹除。
